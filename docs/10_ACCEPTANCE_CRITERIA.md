# 10. Acceptance Criteria

## A. Onboarding

- [ ] 사용자는 권한 허용 전에 스크린샷만 다룬다는 설명을 본다.
- [ ] 권한을 거부해도 수동 선택으로 앱을 체험할 수 있다.
- [ ] 알림 시간 선택은 건너뛸 수 있다.
- [ ] 온보딩 완료 상태가 로컬에 저장된다.

## B. Import & Analysis

- [ ] 앱은 mock 또는 실제 입력에서 새 스크린샷 목록을 만든다.
- [ ] 각 항목은 이미지, 캡처 시각, 출처, 분석 상태를 가진다.
- [ ] 분석 실패 항목만 재시도할 수 있다.
- [ ] 유사 항목은 하나 이상의 그룹 후보로 표시된다.

## C. Today

- [ ] 오늘의 미정리 개수와 그룹 수가 보인다.
- [ ] 예상 정리 시간이 표시된다.
- [ ] 의도별 카운트가 표시된다.
- [ ] 새 항목이 없을 때 명확한 빈 상태가 나온다.
- [ ] 진행 중인 리뷰가 있으면 이어서 시작할 수 있다.

## D. Review

- [ ] 묶음을 열면 개별 캡처를 모두 읽지 않아도 내용 요약과 묶은 근거가 보인다.
- [ ] 하나씩 확인에서는 민감하지 않은 캡처의 사실 중심 요약이 보인다.
- [ ] 민감한 캡처는 제목뿐 아니라 요약과 묶은 근거도 기본으로 가린다.
- [ ] 사용자는 묶음을 한 번에 승인할 수 있다.
- [ ] 사용자는 묶음 안의 일부만 수정할 수 있다.
- [ ] 의도 변경은 2탭 이내다.
- [ ] 그룹 병합과 분리가 가능하다.
- [ ] 제거 후 실행 취소가 가능하다.
- [ ] 사용자는 각 항목을 열지 않고도 리뷰를 끝낼 수 있다.

## E. Library

- [ ] 2열 그리드가 원본 비율을 안정적으로 표시한다.
- [ ] 5개 의도와 전체 필터가 동작한다.
- [ ] 민감 항목은 기본 블러다.
- [ ] 긴 캡처가 레이아웃을 무한히 늘리지 않는다.
- [ ] 다중 선택 모드가 동작한다.

## F. Search

- [ ] 제목, OCR 텍스트, 출처, 의도, 날짜로 검색 가능하다.
- [ ] 검색 결과에 매칭 단서가 보인다.
- [ ] 결과 없음 상태가 검색 개선 방법을 안내한다.
- [ ] 검색 결과에서 상세 화면으로 이동한다.

## G. Detail & Delete

- [x] 상세에서 원본을 전체 화면으로 열고 1–4배 확대·축소·화면 맞춤을 사용할 수 있다.
- [x] 상세에서 캡처 시각과 로컬 보관 기록을 확인할 수 있다.
- [x] 민감 항목은 원본 확대와 캡처 기록 집계를 노출하지 않는다.
- [ ] 상세에서 의도, 제목, 컬렉션을 수정할 수 있다.
- [x] 앱 제거와 기기 원본 삭제가 분리돼 있다.
- [x] 기기 삭제는 앱 확인과 OS 삭제 성공을 요구한다.
- [x] 기기 삭제 실패·취소·권한 거부 시 원래 항목을 유지한다.
- [x] 중단된 삭제 요청은 재실행 시 원본 존재 여부로 복구한다.
- [ ] 민감 콘텐츠를 공유하려 할 때 경고가 나온다.

## H. Design system

- [ ] 모든 색상과 간격은 토큰에서 온다.
- [ ] 의도는 색상 외에 아이콘과 텍스트로 구분된다.
- [ ] 기본 인터랙션 영역은 44×44 이상이다.
- [ ] Reduce Motion에서 핵심 흐름이 유지된다.
- [ ] 텍스트 크기 확대 시 주요 CTA가 잘리지 않는다.

## I. Analytics

- [ ] 핵심 이벤트가 정의된 이름으로 기록된다.
- [ ] OCR 원문과 이미지 원본이 분석 이벤트에 포함되지 않는다.
- [ ] 리뷰 완료 시간과 수정률을 계산할 수 있다.

## J. Demo readiness

- [ ] 최소 20개의 현실적인 한국어 mock 스크린샷 메타데이터가 있다.
- [ ] 5개 의도가 모두 샘플에 포함된다.
- [ ] 중복, 긴 캡처, 민감 항목, 분석 실패 샘플이 포함된다.
- [ ] 첫 실행부터 리뷰 완료까지 데모가 끊기지 않는다.

## K. Useful Recall

- [x] 다시 보기 후보는 승인된 `saved` 항목에서만 선정된다.
- [x] 민감·완료·만료·추천 제외·snooze 중 항목은 후보가 되지 않는다.
- [x] 의도별 최소·기본·최종 시간 창이 분리돼 있다.
- [x] 기본 시간 창을 지난 항목은 정확한 엔티티와 추가 단서가 있을 때만 부활한다.
- [x] 최근 열람과 최근 노출에 각각 cooldown이 적용된다.
- [x] 후보는 하루 최대 3개이며 같은 의도·출처의 과점을 제한한다.
- [x] 일별 후보 순서는 고정되고, 제거된 후보를 같은 날 몰래 보충하지 않는다.
- [x] 노출·열기·snooze·완료·제외·복구 이력을 별도 로컬 read model에 저장한다.
- [ ] Today에서 `다시 보는 이유`와 열기·나중에·완료·제외 행동을 제공한다.

## L. Third Signal Action Draft

- [x] 승인된 비민감 `saved` 캡처가 최소 세 장인 그룹만 후보가 된다.
- [x] 세 캡처의 의도가 같고, 서로 다른 단서가 있으며, 의도별 유효 기간 안에 있어야 한다.
- [x] 중복·검토 필요·민감·삭제·완료·대체 그룹은 제안 전에 fail closed한다.
- [x] 사고 싶음·참고·읽기·공유는 각각 결정 카드·보드·브리프·공유 초안 하나로 매핑된다.
- [x] 네 번째 캡처가 들어와도 같은 최초 세 장으로 중복 제안을 만들지 않는다.
- [x] Today에는 실제 캡처 triptych와 primary action 하나만 노출한다.
- [x] 수락·그대로 보관 반응은 로컬에 저장되고 같은 제안을 반복하지 않는다.
- [x] 제안과 interaction history에 OCR 원문·이미지·벡터·hidden reasoning을 저장하지 않는다.
- [ ] 실제 초안의 완료·공유·구매·활용 결과를 별도 로컬 이벤트로 기록한다.
