# 08. Privacy & Safety Requirements

## 기본 가정

스크린샷에는 다음이 포함될 수 있다.

- 사내 기밀
- 메신저 대화
- 주소와 연락처
- 주문번호
- 결제/금융 정보
- 인증 코드
- 건강 정보
- 타인의 얼굴과 계정명

## 원칙

1. 최소 권한
2. 로컬 처리 우선
3. 원본 자동 삭제 금지
4. 공유 전 명시적 확인
5. 민감 항목 기본 제외
6. 데이터 위치를 사용자에게 설명

## Permission UX

권한 요청 전 설명 화면을 제공한다.

> 새로 생긴 스크린샷만 찾아 정리합니다. 일반 사진은 보관함에 표시하지 않습니다.

권한 거부 시:

- 수동 선택 경로 제공
- 기능 차이를 설명
- 설정으로 이동 버튼 제공

## Sensitive detection

탐지 후보:

- 카드번호 패턴
- 계좌번호/송금 화면
- 주소
- 전화번호/이메일
- OTP/인증번호
- 대화형 UI
- 회사 문서 키워드
- 신분증/티켓 바코드

오탐 가능성을 전제로 `민감함`은 수정 가능해야 한다.

## Sharing defaults

- 민감 항목: 제외
- 대화: 제외
- 회사 컬렉션: 제외
- 위치/주소: 블러
- 원본 전체 해상도: 기본 비활성
- 워터마크/출처 표기: 가능한 경우 유지

## Delete semantics

두 액션을 절대 합치지 않는다.

1. `앱에서만 제거`
2. `기기 사진에서도 삭제`

기기 삭제는:

- 명시적 확인
- 영향 설명
- 가능하면 OS 권한 다이얼로그 사용
- 사진 앱의 최근 삭제 앨범 안내
- OS 삭제 성공 뒤에만 로컬 상태 확정
- 실패·취소·권한 거부 시 원래 상태 유지

Catch 내부 Undo는 `앱에서만 제거`에만 제공한다. 사진 앱 삭제에는 복구를 보장하는 것처럼 보이는 자체 Undo를 제공하지 않는다.

## App lock

구조상 지원:

- 생체 인증
- 앱 전환기 썸네일 가리기
- 잠금 전 민감 이미지 렌더링 금지

## Telemetry

분석 이벤트에 다음을 넣지 않는다.

- OCR 원문
- 이미지 원본
- 개인 식별 정보
- 검색어 원문을 기본 수집하지 않음
- 요약 근거 원문과 이미지 임베딩
- 모델의 prompt, 숨은 사고 과정, raw 응답

수집 가능한 이벤트는 `docs/09_ANALYTICS_AND_VIRAL.md`의 익명 구조를 따른다.

## Summary processing

- OCR 텍스트가 충분하면 텍스트 경로만 사용하고 원본 이미지 전송을 피한다.
- 이미지 경로는 원본을 해석할 수 있으므로 기본은 온디바이스 또는 명시적 동의가 있는 adapter다.
- 이미지 vector는 민감한 파생 데이터로 취급하며 현재 MVP에서는 분석 중 메모리에만 둔다.
- 향후 vector index를 추가하면 메인 JSON snapshot·analytics·cloud sync 밖의 별도 로컬 저장소를 사용하고, 항목 삭제 시 함께 제거한다.
- 사용자에게는 모델의 내부 reasoning 대신 원본에서 재확인 가능한 짧은 단서만 보여준다.
- 민감 항목은 요약 본문뿐 아니라 근거, 접근성 라벨, 검색 매치에서도 원문을 노출하지 않는다.
