## S10. Today

### Header

- Echo wordmark와 인라인 `기기 내 처리` 상태. 상태를 pill이나 알림 점으로 만들지 않는다.
- 날짜: `8월 20일 목요일`
- `오늘 함께 볼 3묶음`
- 현재 리뷰 진행 상태 또는 예상 정리 시간

### Start action

- Primary CTA: `오늘 정리 시작`
- Today 포스트에서는 상태를 바꾸지 않고 Review로만 이동한다.

### Intent summary

첫 캡처를 아래로 밀지 않는 compact 가로 목록으로 개수만 보여준다. 각 항목은 파스텔 pill이 아닌 중립 텍스트와 작은 아이콘으로 표현한다:

- 참고 4
- 사고 싶음 3
- 공유 2
- 읽기 1
- 간직 2

### Group preview

- 최대 3개의 동일한 `RecallPost`를 세로로 보여준다.
- 각 포스트는 `출처/장수 → 큰 스크린샷 pager → 위치 표시 → 제목 → 함께 묶인 이유 → intent` 순서다.
- 묶음 안의 캡처만 좌우로 넘긴다. 화면 전체 세로 snap과 자동재생은 사용하지 않는다.
- 실제 캡처는 내용 손실을 막기 위해 `contain`으로 표시한다. 데모용 코드 장면만 프레임을 채우며, 전체 원본은 Review/상세에서 확인한다.
- 첫 포스트만 크게 만들거나 나머지를 요약 행으로 줄이지 않는다.
- 좋아요·댓글·팔로우·공개 프로필·조회 수·추천 피드는 없다.
- 마지막에는 `오늘의 피드 끝`과 Review CTA를 반드시 보여준다.

### Secondary sections

- 분석 실패는 피드를 막지 않는 짧은 인라인 알림으로 표시한다.
- 지난 정리가 있으면 상단/종료 CTA가 `정리 이어하기`로 바뀐다.

### Empty state

- `오늘은 새로 주운 장면이 없어요.`
- `스크린샷이 생기면 여기에 조용히 모아둘게요.`

## S32. Screenshot Detail & Device Delete

### Content

- 원본 스크린샷과 사실 중심 요약
- 의도, 출처, 캡처 시각
- `원본 크게 보기`: 전체 화면 `contain`, 1–4배 확대·축소·화면 맞춤, 확대 후 이동
- `이 장면의 기록`: 캡처한 때, 보관함 전체 기록, 같은 분류·출처의 장수, 활성 그룹이 있을 때 함께 묶인 장수
- `Catch에서만 제거`와 `기기 사진에서도 삭제`를 분리한 정리 영역

### Device delete flow

1. 승인되어 보관된 캡처에서만 삭제 CTA를 노출한다.
2. 앱 확인 패널에서 Catch와 사진 앱 양쪽에서 사라짐을 설명한다.
3. iOS/Android 시스템 삭제 확인을 실행한다.
4. OS 성공 뒤에만 `deleted_from_device` tombstone을 저장한다.
5. 실패·취소·권한 거부에서는 기존 항목을 그대로 유지한다.
6. 성공 후 사진 앱의 `최근 삭제된 항목` 복구 경로를 안내한다.

### Rules

- 활성 리뷰의 미승인 항목은 먼저 묶음을 보관해야 한다.
- 앱 내부 제거에는 실행 취소가 가능하지만, 사진 앱 삭제에는 가짜 Undo를 제공하지 않는다.
- 민감 항목의 확인 화면에서도 원본·OCR·제목을 다시 노출하지 않는다.
- 기록은 현재 기기의 로컬 항목과 실제 그룹만 집계한다. 조회 횟수·유사도·빈도는 저장하거나 계산하지 않았다면 추측하지 않는다.
- 민감 항목은 원본 확대 진입을 제공하지 않고 기록의 제목·출처·날짜·집계도 보호한다.

## S40. Search

### Search field placeholder

`기억나는 장면이나 이유를 적어보세요`

검색 소개와 추천 검색은 흰 면·회색 구분선을 사용한다. 장식용 orbit, 컬러 코너, 파스텔 강조 면은 사용하지 않는다.

### Suggestions

- `지난달 경쟁사 이벤트`
- `인스타에서 본 검정 러닝화`
- `공유하려던 뉴스`

### Result card

- 이미지
- 제목
- 매칭 단서: `“러닝화”, Instagram, 사고 싶음`
- 날짜

### No result

`출처, 시기, 색상, 상품명처럼 기억나는 단서를 더해보세요.`
