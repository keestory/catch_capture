# Phase 2 Verification

검증일: 2026-08-22

## 구현 범위

- 가치 제안, 개인정보 사전 안내, 정리 시간 3단계 온보딩
- 온보딩 draft와 완료 상태의 별도 AsyncStorage 저장
- 전체 접근, 선택 접근, 거부, 수동 선택, 예시 데이터 분기
- 권한 거부 후 재요청 강요 없이 대체 경로 제공
- 알림 권한과 정리 시간 선택 분리
- 정리 시간 선택 뒤 실제 로컬 데이터로 첫 결과 증거 화면 표시
- 첫 결과에서 온보딩을 완료한 뒤 동일한 세 묶음의 리뷰 세션으로 연결
- 첫 묶음 승인 후 승인 항목을 즉시 검색하는 재발견 CTA

## 자동 검증

`npm run verify` 결과:

- Prettier 통과
- ESLint 경고 0
- TypeScript strict 통과
- Vitest 16개 파일, 91개 테스트 통과

온보딩 테스트는 개인정보 안내 전 권한 요청 차단, full/limited 완료, denied→manual, denied→demo, 수동 선택 취소, 재실행 persistence, 손상된 저장 데이터 복구를 포함한다.

첫 결과 테스트는 리뷰 대상 장수·묶음 수를 실제 데이터로 계산하고, 민감 항목과 그래픽 placeholder를 증거 이미지에서 제외하며, 최근 장면과 지난 장면을 함께 고르는 동작을 포함한다.

## 모바일 화면 검증

390×844 viewport에서 별도 신규 사용자 origin으로 확인했다.

- full → 오후 8:00 → Today
- limited → 오후 9:30 → Today
- denied → 예시 캡처 → 나중에 설정 → Today
- manual selection → 나중에 설정 → Today
- 첫 묶음 `모두 참고로 보관` → `방금 보관한 장면 찾아보기`
- `경쟁사 장바구니`가 자동 입력되고 승인한 2장이 검색됨
- 브라우저 warning/error 0건

2026-08-22에는 별도 신규 origin에서 `denied → 예시 캡처 → 나중에 설정 → 7장/3묶음 첫 결과 → 첫 묶음 리뷰`를 추가 확인했다. 첫 결과에는 평가용 실제 캡처 3장, 측정된 자동 정리 수치, 지난 장면 재발견 수치가 표시됐고 리뷰 URL은 `session-2026-08-21-1`로 이어졌다. 콘솔 error는 0건이었다.

## 검증하지 않은 경계

PhotoKit/MediaStore 실제 권한, 시스템 사진 선택기, 선택 asset import, iOS 설정 복귀 후 권한 재동기화, 실 OCR과 알림 예약은 검증 완료로 간주하지 않는다. 데모 분기는 평가용 로컬 캡처를 사용한다. 평가용 캡처 9장은 release check에서 의도적으로 차단되므로 실제 배포 전에는 사용자 평가 에셋을 제거하거나 별도의 개발 빌드 정책을 확정해야 한다.
