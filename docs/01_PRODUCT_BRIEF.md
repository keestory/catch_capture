# 01. Product Brief

## 문제

사용자는 업무 레퍼런스, 상품, 소셜 콘텐츠, 뉴스, 대화, 장소 등을 스크린샷으로 저장하지만 다시 찾거나 활용하지 못한다.

기존 사진첩의 문제는 다음과 같다.

- 스크린샷이 일반 사진과 섞인다.
- 무엇을 위해 캡처했는지 남지 않는다.
- 캡처 직후 분류하는 것은 귀찮다.
- 시간이 지나면 검색어가 기억나지 않는다.
- 정리가 필요한 양이 많아질수록 앱을 열기 싫어진다.

## 사용자 니즈

사용자는 폴더를 관리하고 싶은 것이 아니라 다음을 원한다.

- “내가 왜 이걸 캡처했는지 알아서 정리해줘.”
- “오늘 찍은 것만 한 번에 확인하고 끝내고 싶어.”
- “전에 봤던 검정 러닝화, 엄마에게 보내려던 기사처럼 기억나는 방식으로 찾고 싶어.”
- “민감한 회사 자료나 대화가 잘못 공유되지는 않았으면 좋겠어.”

## 제품 약속

> 하루 동안 생긴 스크린샷을 조용히 묶어두고, 사용자가 30~60초 안에 확인하도록 돕는다.

## 핵심 사용자

### 1. 레퍼런스 수집형 직장인

- 경쟁사 UI, 마케팅, 콘텐츠, 가격, 프로모션을 자주 캡처한다.
- 프로젝트별로 다시 찾고 싶다.
- 회사 관련 캡처는 외부 공유가 위험하다.

### 2. 취향 수집형 쇼퍼

- 패션, 뷰티, 인테리어, 여행, 식당을 자주 캡처한다.
- 나중에 비교하거나 구매하고 싶다.
- 상품명이나 브랜드를 정확히 기억하지 못한다.

### 3. 공유 지연형 소셜 사용자

- 재미있거나 공감되는 장면을 캡처하지만 곧바로 보내지는 않는다.
- 며칠 뒤에는 공유하려던 이유를 잊는다.

### 4. 읽기 축적형 정보 사용자

- 뉴스와 긴 글을 캡처한다.
- 저장은 하지만 다시 읽지 못한다.

## 핵심 차별점

1. 출처가 아니라 캡처 의도를 중심으로 정리한다.
2. 한 장씩 분류하지 않고 묶음 단위로 승인한다.
3. 하루 한 번의 리추얼로 정리 부담을 낮춘다.
4. 자연어 기억 단서로 다시 찾는다.
5. 공유 가능한 결과물은 원본 캡처가 아니라 사용자가 고른 큐레이션이다.

## 성공 경험

사용자는 밤에 알림을 열고 다음과 같은 화면을 본다.

> 오늘 12장을 주웠어요. 4개의 묶음으로 정리했어요.

사용자는 네 번의 승인으로 정리를 끝낸다. 며칠 뒤 “인스타에서 본 검정 러닝화”를 검색해 해당 캡처를 찾고, 원본 링크나 구매 후보 컬렉션으로 이동한다.

## 비목표

MVP에서 다음은 하지 않는다.

- 일반 사진 전체 관리
- 공개형 소셜 네트워크
- 무제한 클라우드 백업
- 완전 자동 삭제
- 모든 외부 앱의 원본 링크 복구 보장
- 기업용 협업 워크스페이스
- 대화형 AI 비서 중심 UX
