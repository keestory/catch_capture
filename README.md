# Catch Capture

오늘 캡처한 화면을 `참고`, `사고 싶음`, `공유`, `읽기`, `간직` 의도로 묶어 하루 한 번 정리하는 모바일 앱입니다. 현재 기본 구현은 Expo/React Native/TypeScript이며, 기존 SwiftUI 프로토타입도 비교 검증을 위해 그대로 보존했습니다.

## 핵심 제품 원칙

스크린샷은 파일이 아니라 사용자가 잠깐 멈춰 둔 의도입니다. Catch는 폴더를 늘리는 대신 `맥락 + 다음 행동`으로 정리합니다.

- 회사 + 참고하기
- 쇼핑 + 사고 싶음
- 소셜 + 공유/간직하기
- 뉴스 + 나중에 읽기/공유하기

AI가 먼저 제안하고 사용자는 하루 한 번 맞는지만 확인합니다. 앱의 목표는 체류 시간을 늘리는 피드가 아니라 2~3분 안에 정리를 끝내는 것입니다.

## 웹 우선 MVP 실행

Node.js 22.13 이상이 필요합니다.

```bash
npm install
npm run web
```

브라우저 온보딩에서는 두 경로를 제공합니다.

- PNG/JPG/WebP 스크린샷 최대 6장을 직접 선택
- 서버 전송 없이 준비된 한국어 데모로 바로 체험

웹은 사진 보관함을 자동으로 탐색하지 않으며, 백그라운드 자동 정리와 기기 원본 삭제를
지원하는 것처럼 표시하지 않습니다. 네이티브 탐색이 필요할 때는 아래 명령을 사용합니다.

```bash
npm start
npm run ios
npm run android
```

전체 정적 검증과 테스트:

```bash
npm run verify
```

배포용 웹 정적 파일 생성:

```bash
npm run export -- --platform web
```

완료된 결과는 `dist/`에 생성됩니다.

## SwiftUI 프로토타입

기존 네이티브 탐색은 `CatchCapture/`와 `CatchCapture.xcodeproj`에 남아 있습니다. 실행에는 Xcode 26 이상과 iOS 17 이상이 필요합니다.

```bash
xcodegen generate
open CatchCapture.xcodeproj
```

- 총 17장·10개 묶음 완료 후 `경쟁사 장바구니` 검색 결과 2장을 수정된 `간직` 상태로 재발견

권한과 스크린샷 가져오기는 Expo MediaLibrary SDK 57 class API에 연결돼 있습니다. 새 설치의 실제 사진 모드는 빈 저장소에서 시작하고, demo 모드만 준비된 mock을 사용합니다. `앱에서만 제거`는 Echo의 로컬 색인에서만 제외하며, `기기 사진에서도 삭제`는 가져올 때 저장한 실제 MediaLibrary asset ID로 원본 삭제를 요청합니다. 실제 iPhone의 시스템 권한창, 제한 접근 변경, 삭제 확인, 사진 앱의 최근 삭제 항목 이동은 signed development build의 물리 기기 QA가 필요합니다. 실 OCR·이미지 임베딩 모델, 정확한 백그라운드 실행과 민감 영역 탐지는 후속 네이티브 구현 범위입니다.

## 플랫폼 제약

iOS는 백그라운드 작업의 정확한 실행 시각을 보장하지 않습니다. Catch의 약속은 “매일 정확히 9시에 자동 완료”가 아니라, 시스템이 허용할 때 미리 준비하고 오후 9시 알림을 열면 최신 인박스를 빠르게 확인하는 경험입니다.

사진 앱의 공개 메타데이터만으로 캡처 원본 앱이나 원본 URL을 확정할 수도 없습니다. 확인되지 않은 링크는 만들지 않습니다.

로드맵은 `tasks/TASKS.md`, 기술 판단은 `DECISIONS.md`, 상세 제품 기준은 `docs/`를 참고하세요.
